## 1. システムの目的

社員が立て替えた経費の申請から、上長の承認、経理部での精算までを
一元的に管理する。紙の申請書と押印による運用を廃止し、
月次の精算処理にかかる工数を削減することを目的とする。

## 2. 利用者と権限

| ロール | 値 | できること |
|---|---|---|
| 申請者 | `employee` | 自分の経費を申請する。自分の申請を取り下げる。 |
| 承認者 | `approver` | 部下の申請を承認・却下する。 |
| 管理者 | `admin` | 全申請の参照、CSV出力。 |

## 3. 業務フロー

```
[申請者] 経費を申請する
              ↓  status: submitted
[承認者] 内容を確認して承認 or 却下
              ↓  status: approved / rejected
[経理部] 月次で集計しCSV出力 → 給与システムへ連携
```

申請者は、承認される前であれば申請を取り下げて下書きに戻すことができる。

## 4. 経費カテゴリ

経費は以下の5区分で管理する。
税率・上限額はマスタテーブル `m_expense_category` で管理し、
税制改正や社内規程の変更時はマスタの更新のみで対応できるようにする。

| 区分 | コード | 消費税率 | 上限額 | 上限の単位 | 備考 |
|---|---|---|---|---|---|
| 交通費 | `transport` | 10% | 50,000円 | 1申請あたり | 公共交通機関のみ。タクシーは要事前申請 |
| 宿泊費 | `lodging` | 10% | 30,000円 | 1泊あたり | |
| 接待費 | `entertainment` | 10% | 10,000円 | 参加者1名あたり | 参加人数の入力を必須とする |
| 物品費 | `goods` | 10% | 100,000円 | 1申請あたり | 10万円以上は資産計上のため経費申請不可 |
| その他 | `other` | 10% | 30,000円 | 1申請あたり | 内容の記載を必須とする |

### 4.1 金額計算の規則

* 消費税額は「小計 × 税率」を計算し、**円未満は四捨五入**する。
* 合計金額は「小計 + 消費税額」とする。
* 金額はすべて**日本円の整数**として扱う。小数は保持しない。
* 外貨で支払った経費は、支払日の社内レートで円換算してから申請する。

### 4.2 上限額のチェック

* 上限額を超える申請は**受け付けない**。
* 上限額の判定は**合計金額（税込）**で行う。
* 上限を超えた場合、システムは金額を自動調整せず、エラーとして申請者に差し戻す。

### 4.3 月次予算枠

社員ごとに月次の予算枠（既定200,000円）を設定する。
申請時点で「当月の使用済み金額 + 今回の申請額」が予算枠を超える場合は受け付けない。

使用済み金額は**承認された時点**で加算し、**取り下げられた時点**で減算する。

## 5. 対象月の扱い

申請には対象月（`YYYY-MM` 形式）を必ず持たせる。

* 申請者が対象月を指定した場合は、その値を使用する。
* 指定がない場合は、**申請日の属する月**を対象月とする。
* 対象月は月次集計・予算枠の突き合わせのキーとなるため、
  カテゴリによって決定方法が変わることはない。

## 6. 申請ステータス

ステータスは以下の4値のみを取る。

| 値 | 意味 |
|---|---|
| `draft` | 下書き（取り下げ後もこの状態に戻る） |
| `submitted` | 申請中（承認待ち） |
| `approved` | 承認済み |
| `rejected` | 却下 |

画面ではステータスに応じたバッジを表示する。

## 7. レシート画像

* 1件の申請に対して複数枚のレシート画像を添付できる。
* 添付できる形式は JPEG / PNG。
* 一覧画面ではサムネイル、詳細画面では表示用画像を表示する。
* レシートの原本は電子帳簿保存法の要件に従い7年間保持する。

## 8. API仕様

### 8.1 共通事項

* リクエスト・レスポンスはいずれも `application/json`。
* 日時は **ISO 8601 形式の文字列**で返す（例：`2026-07-25T09:15:00.000Z`）。
* 正常時は HTTP 200、入力不備は 400、対象が存在しない場合は 404、
  サーバ側の異常は 500 を返す。それ以外のステータスコードは使用しない。
* エラー時のレスポンスは以下の形式とする。

```json
{ "error": "エラーコード", "message": "利用者向けメッセージ" }
```

| エラーコード | HTTPステータス | 発生条件 |
|---|---|---|
| `VALIDATION_ERROR` | 400 | 必須項目の不足、形式不正 |
| `LIMIT_EXCEEDED` | 400 | カテゴリの上限額を超過 |
| `BUDGET_EXCEEDED` | 400 | 月次予算枠を超過 |
| `NOT_FOUND` | 404 | 対象の申請が存在しない |

### 8.2 経費の申請

```
POST /api/reports/{category}
```

`{category}` には 第4章 の区分コードを指定する。

リクエスト:

```json
{
  "userId": 1,
  "title": "7/20 顧客訪問 交通費",
  "targetMonth": "2026-07",
  "attendeeCount": 3,
  "items": [
    { "description": "電車代（往復）", "unitPrice": 1200, "qty": 1 }
  ]
}
```

| 項目 | 必須 | 説明 |
|---|---|---|
| `userId` | ○ | 申請者の社員ID |
| `title` | ○ | 件名 |
| `targetMonth` | | 対象月。省略時は申請日の月 |
| `attendeeCount` | 接待費のみ○ | 参加人数 |
| `items` | ○ | 明細（1〜50件） |

レスポンス（200）:

```json
{
  "success": true,
  "data": {
    "reportId": 1024,
    "category": "transport",
    "status": "submitted",
    "subtotal": 1200,
    "tax": 120,
    "total": 1320,
    "targetMonth": "2026-07",
    "submittedAt": "2026-07-25T09:15:00.000Z",
    "items": [
      { "description": "電車代（往復）", "unitPrice": 1200, "qty": 1, "amount": 1200 }
    ]
  }
}
```

`data.items` は明細の配列とし、カテゴリによってキー名が変わることはない。

### 8.3 申請の一覧・詳細

```
GET /api/reports?userId={userId}&status={status}&limit={limit}
GET /api/reports/{reportId}
```

一覧は申請IDの降順で返す。`limit` の既定値は20、最大100。

### 8.4 承認・却下・取り下げ

```
POST /api/reports/{reportId}/approve    { "approverId": 8,  "comment": "" }
POST /api/reports/{reportId}/reject     { "approverId": 8,  "comment": "" }
POST /api/reports/{reportId}/withdraw   { "userId": 1,      "comment": "" }
```

いずれも処理後の申請ステータスを返す。

```json
{ "success": true, "data": { "reportId": 1024, "status": "approved" } }
```

承認・取り下げは月次予算枠の使用済み金額を更新するため、
申請と予算枠の整合性が保たれるように排他制御を行う。

### 8.5 レシート画像

```
POST /api/receipts/upload    { "reportId": 1024, "filename": "IMG_0001.jpg", "imageBase64": "data:image/jpeg;base64,..." }
GET  /api/receipts/{id}/thumb
GET  /api/receipts/{id}/raw
```

アップロードされた画像は、一覧表示用のサムネイル（幅80px）と
詳細表示用の画像（幅600px）を生成して保持する。

### 8.6 集計・出力

```
GET /api/summary/{userId}/{month}
GET /api/export/{month}
```

月次集計はカテゴリ別の件数と合計金額、および申請の一覧を返す。
CSV出力は経理部が給与システムに取り込むために使用する。

### 8.7 ヘルスチェック

```
GET /api/health
```

## 9. 非機能要件

| 項目 | 目標値 |
|---|---|
| 同時利用者数 | 50名（月末は全社員200名が集中する想定） |
| 画面応答時間 | 一覧・詳細は1秒以内 |
| レシート添付 | 添付操作の完了まで3秒以内 |
| 稼働時間 | 平日 8:00〜22:00 |
| データ保持 | 申請データ・レシート原本は7年間 |

## 10. 制約事項

* 社内の一部端末（Windows 7 + IE11）からの利用を想定する。
* 画面は社内標準解像度（1280×1024）を前提とした固定幅レイアウトとする。
  表の桁位置がずれないことを経理部の要件として優先する。
* **スマートフォン・タブレットからの利用は想定しない。**
  社外から社内ネットワークへ接続する手段が無いため（2019年3月時点）。
* 給与システムとの連携はCSVファイルの受け渡しによる。
